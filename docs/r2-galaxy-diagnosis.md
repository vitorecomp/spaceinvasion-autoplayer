# R2 Diagnosis & Fix Report: Universe / Galaxy View Stalls, Page-View Throttling, and Attack / Exploration Reliability

**Scope:** Milestone `M2-r2-galaxy-throttle-fix` & live verification hardening (`spaceinvasion/client.py`, `spaceinvasion/fleet.py`, `spaceinvasion/storage.py`, `spaceinvasion/executor.py`, `spaceinvasion/strategy.py`, `spaceinvasion/api_server.py`, `spaceinvasion/logging_utils.py`, `commander.py`).

---

## 1. Executive Summary

Opening the SpaceInvasion Classic Universe/Galaxy view (`internalGalaxy`) and running exploration/attack flows stalled or failed from **seven interacting defects** (five initial R2 defects plus two live-verified 2D Galaxy / modal DOM defects):

1. **Missing `F_Navi` link selector (`a[href*="action=internalGalaxy"]`), click interception, & `p_galaxy()` popup focus theft**: SpaceInvasion Classic renders the Galaxy menu item as `<a href="#" onclick="p_galaxy()">` bordered by `<td class="rahmen"></td>`, causing `NoSuchElementException` / `ElementClickInterceptedException` (HTTP `500`) until replaced with `SI_TPL.menu.sid` + `p_galaxy()` fallback; furthermore, `p_galaxy()` can open a frameless `"Galaxy"` popup window that steals WebDriver focus until `ensure_in_game()` switches back via `find_and_switch_game_tab()`.
2. **False-positive server throttle triggered by unpopulated `#pageview-amount` modal on `internalGalaxy`**: Every normal 2D `internalGalaxy` response embeds a hidden AJAX error modal template (`You've made more than <span id="pageview-amount"></span> page views at last minute.`). Substring matching `"made more than" in low and "page views" in low` tripped a false `RateLimitError` (`45s` cooldown) on every Galaxy load even well below the `24/min` cap until `is_server_rate_limit_html()` stripped unpopulated `<span id="pageview-amount">` placeholders.
3. **2D Graphical Galaxy DOM (`SI_TPL.galaxy` + `div.planet-hit`) & async `si.getData()` rendering**: Live SpaceInvasion Classic renders a 2D graphical map populated asynchronously via `SI_TPL.galaxy` (`si.getData()`) using `div.planet-hit` nodes (`g`/`s` params, `#c9d324` yellow inactive, `#347187` blue vacation/newbie, `#496c2a` green own/alliance, `opacity:0.6` / `0px 0px 2px #fff` spectral white, `.spacia-planet`, `.rubble-orbit`/`[name="rubblefield"]`, `[name="astro"]`/`[id^="astro-"]`) alongside own-planet header badges (`#planet-coords`, `#planet-list`), returning `0` slots to table-only `<tr>` parsers until `_wait_galaxy_ajax_ready()` and the 2D `div.planet-hit` parser were added.
4. **Per-instance pacing reset & unbudgeted page-view bursts (`~17–25` views/action tick)**: `GameApiBridge` constructed a fresh `GameBrowserClient` (`_last_nav_at = 0.0`) on every HTTP call with no shared rolling 60-second page-view cap, no pacing on `read_planets_overview(refresh=True)` or `ActionExecutor` submits, redundant `read_full_snapshot(include_buildings=True)` + forced `navigate_menu("internalHome")` after `scan_galaxy`, and unconditional `include_shipyard=True`/`include_research=True` polls.
5. **Energy-coupled Blast furnace (`b2`) `0% <-> 100%` oscillation & `0%` Metal deadlock**: Throttling `b2` L11 to `0%` freed `102` energy (`energy_used: 783 -> 681`), hiding `P1 Fusion plant L14` and surfacing `P2 Development center L5` (missing Metal), which immediately resumed `b2` to `100%` (`energy_used -> 783`), repeating every `~40s`; conversely, on high-level colonies (`b2` L18), `form[name="economy"]` required clicking `input[value="Calculate"]`, reserving latent `b2` energy, expanding storage-capped warehouses (`b11`–`b14`), and syncing live `resource2` via `<form id="ress">` `#metall` + `300s` `sync_economy` checks.
6. **Missing cooldown handling & retry storm**: `RateLimitError` inherited from `SpaceInvasionAuthError` without cooldown state, causing `api_server.py` to return generic HTTP `503` (or flip `in_game=False` / trigger re-login) while `commander.py` slept `3.0s` instead of `>= 45s` and re-hit the throttled server.
7. **Stale frame waits & live `internalFleet` / `internalSendFleetFinish` DOM quirks**: `_wait_frame_ready()` lacked a pre-navigation DOM token (`window.__siNavToken`); `ActionExecutor` risked touching `internalFleet`'s target-favourites `<select name="planet">` and needed JS `input`/`change` event dispatch for `maxlength`/`onblur` fields plus `form[action*="internalSendFleetFinish"]` `#goButton` launch selectors and `fleetErr.*` error checks.

## 3. Root Causes in Detail

### 3.1 Page-View Amplification Math (Before vs. After)

| Flow | Views Before | Root Amplification Drivers | Views After |
|---|---|---|---|
| **Idle Commander tick** (`20s` interval) | **4–6 views/tick** (`12–18/min`) | `get_state(include_buildings=True)` forced `F_planets` reload + `internalHome` + `internalBuildings` + `internalWeaponFactory` + `internalHome` on every 20s poll | **1–2 views/tick** (`~4–6/min`) via light `include_buildings=False` polling (full buildings every `60s` or when `WAIT_RESOURCES` becomes affordable), `return_home=False`, and `60s`/`120s` research/shipyard TTLs |

### 3.2 Rate-Limit Cooldown & Retry Storm
- `RateLimitError` previously had no `retry_after` field and triggered no shared cooldown, while all five `except SpaceInvasionAuthError` blocks in `spaceinvasion/api_server.py` (`ensure_debug_browser_ready`, `health`, `dashboard`, `Handler.do_GET`, `Handler.do_POST`) treated rate-limiting as auth loss (`in_game = False`, HTTP `503`, or re-login).
- Meanwhile, `commander.py` fell back to `time.sleep(3.0)` on `GameApiError`, causing continuous retries during active server throttling, and blocking `45s` inside `GameApiBridge._lock` would exceed `ui/app.js`'s `8s` `/dashboard` and `12s` `/command` abort timeouts.
- **Fix:** `PageViewLimiter` records a `45s` cooldown on `RateLimitError` and fails fast (`max_wait = 8.0s` in `GameApiBridge`) without sleeping inside HTTP locks; `is_server_rate_limit_html()` ignores unpopulated `<span id="pageview-amount">` modal templates on `internalGalaxy` while detecting populated modal counts (`<span id="pageview-amount">30</span>`) and server throttle pages; `api_server.py` catches `RateLimitError` before `SpaceInvasionAuthError`, preserves `in_game=True`, returns HTTP `429` (`Retry-After`, `rate_limited=True`, `retry_after`, descriptive `error`) on `/state` and `/command`, keeps `/dashboard` at HTTP `200` with cached state during cooldown, and `commander.py` uses `compute_rate_limit_backoff()` to sleep `>= max(retry_after, 45.0)s` without calling `ensure_session`.

### 3.3 Blast Furnace (`b2`) Energy-Coupled `0% <-> 100%` Oscillation & Live `0%` Smelting Recovery
- Verified directly against `state/spaceinvasion.db` `planet_snapshots` row 36 (`2026-11-15 03:55:16Z`, `b1=12, b2=11, b3=11, b4=8, b5=13, b7=4, b8=1, b9=2`, `speedup=20x`):
  - `game_data.building_level_stats(2, 11)["energy"] == -102` (matching DB `energy_used = 783` at `100%` vs `681` at `0%`).
  - `game_data.blast_furnace_pig_iron_used(11) * 20.0 == 21,480` Pig iron/h.
  - At `100%` (`net = +31`), `Pig iron mine L13` (`-63` energy) triggered `P1 Fusion plant L14` (Pig-iron bottleneck), so `_plan_blast_furnace_throttle` paused `b2` to `0%`.
  - At `0%` (`net = +133`), `Pig iron mine L13` fit inside spare energy (`133 - 63 = +70 >= 0`), so `P1 Fusion plant L14` disappeared and `P2 Development center L5` (Metal bottleneck) became top blocker — immediately resuming `b2` to `100%` (`net -> +31`), regenerating `P1 Fusion plant L14` on the next tick.
  - Additionally, the resume reserve guard used `max(5000, metal * 2)` (`5,000 < 21,480` Pig iron/h drain at `20x`), creating a threshold inversion, and there was no per-planet temporal cooldown.
- On live Colony `12476` (`b2` L18, `-445` energy), `internalEconomy` also required submitting `form[name="economy"] input[type="submit"][value="Calculate"]` (with `resource6` Thermosolar support), deferring `b2` upgrades while paused at `0%`, reserving/scaling power for latent `b2` energy demand, expanding storage-capped warehouses (`b11`–`b14`) when `P1`/`P2` costs exceed cap, and tracking live `resource2` status via passive `<form id="ress">` `#metall` ticker detection (guarded against full Metal warehouse caps) + `300s` `sync_economy` checks (`MetalProd=ON/OFF` in `commander.py`, `metal_production_by_planet` in `/bot_status`).
- **Fix:** `_plan_blast_furnace_throttle` enforces (a) a `300s` per-planet cooldown via `throttle_cooldowns` (outside negative-energy emergencies), (b) energy-coupling lookahead (`net_if_resumed` vs planned building starvation + `P1` power Pig-iron cost, plus proactive power reservation while `b2 == 0%`), and (c) symmetric hysteresis deadbands (`bf_pig_used_full * 1.5` reserve threshold, `storage_warn_ratio * 0.85` Metal ceiling, `metal_starved_with_positive_pig` recovery, and `bf_pig_used_full * 0.6` minimum Pig iron for deficit-state Metal resume).

### 3.4 Frame Transitions, `open_galaxy`, 2D Galaxy Parser & Exploration Sweep
- `_wait_frame_ready()` uses a pre-navigation JS token (`window.__siNavToken` via `_mark_frame_navigation`) so consecutive `internalGalaxy -> internalGalaxy` and `internalFleet -> internalSendFleet` transitions cannot return stale `readyState == "complete"` DOM, runs `_check_page_guards(html)` unconditionally on every completed frame load, and `ensure_in_game()` automatically recovers tab focus via `find_and_switch_game_tab()` when `p_galaxy()` opens a frameless `"Galaxy"` popup window.
- `open_galaxy_with_coords()` / `open_galaxy()` normalize `SI_TPL.menu.sid` (with/without `sid=`), pass both Classic (`galaxy`/`system`) and 2D (`g`/`s`) URL parameters, wait for async 2D `SI_TPL.galaxy` (`si.getData()`) planet rendering via `_wait_galaxy_ajax_ready()`, and fall back to submitting `galaxy`/`gal`/`g` + `system`/`sun`/`s` inputs if initial URL params land elsewhere.
- `parse_galaxy_system_html()` and `extract_galaxy_system_coords()` parse `SI_TPL.galaxy` metadata (unquoted JS and JSON-quoted keys/values), strip own-planet switcher badges (`#planet-coords`, `#planet-list`) before text fallback, and support Classic `<tr>` tables, Modern `<div>`/`<li>` cards, and SpaceInvasion Classic's live **2D Graphical Map** (`div.planet-hit` slots, `.spacia-planet`, `.rubble-orbit`/`[name="rubblefield"]`, `[name="astro"]`/`[id^="astro-"]`, `#c9d324` yellow inactive, `#347187` blue vacation/newbie, `#496c2a` green own/alliance, and `opacity:0.6` / `0px 0px 2px #fff` spectral white), alongside `parse_spy_messages_html()` for `internalMessages&type=spio`.
- `GameDatabase` adds `galaxy_scans` + `last_spied_ts` on `spy_targets` and fixes `record_spy_report()` so espionage ingestion no longer overwrites `yellow`/`is_inactive` flags into `light_red`. `strategy.py` implements outward spiral `SCAN_GALAXY` exploration (`±15` systems with `1800s` cooldown) and `s10` `SPY` probe planning (including Tutorial spy probe build + scout milestones).

### 3.5 Fleet Dispatch (`internalFleet -> internalSendFleetFinish`), Diagnostics & API Safety
- `_navigate_and_select_planet()` inspects HTML with BeautifulSoup first (preserving zero-overhead fast path when already on target planet) and never touches `internalFleet`'s `<select name="planet">` target favourites — switching via `internalBuildings` (`Select.select_by_value` + `__siNavToken`) before entering `internalFleet`.
